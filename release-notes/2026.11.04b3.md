# 2026.11.04b3

Opt-in test build for [#157](https://github.com/ibasebcast/ha-alarmdotcom/issues/157), on top of 2026.11.04b2.

- Send only the arming options that are turned on, as elahd's integration does. Earlier builds listed every option in each arm and disarm request, set to false. With b2, arming failed with Alarm.com status 422 on a system whose panel may not offer all of those options.
- When Alarm.com declines a panel command with 422, show a message that says so and suggests checking that the system is ready to arm, instead of the raw `Method: post Status Codes: [422]` text.

### What to test

Install this beta in HACS and restart Home Assistant. With all doors and windows closed, try arming home, then disarming, then arming away. Report which commands work. If one fails, report the exact message, and if you can, capture a debug log of that one attempt (**Settings → Devices & Services → Alarm.com → ⋮ → Enable debug logging**, try the command, then **Disable debug logging**). Redact your password, email, address, cookies and tokens before attaching it on the issue page.

[Stable 2026.11.04.3](https://github.com/ibasebcast/ha-alarmdotcom/releases/tag/v2026.11.04.3) remains the rollback version.
