# 2026.11.09

Stable maintenance release for the camera regression in 2026.11.06 and missing water valves.

- **Camera transport (#177, #172):** Restore endToEnd preference by default, matching 2026.11.04.3. When endToEnd information is absent, Janus is still used. Accounts that need Janus can select **Settings → Devices & Services → Alarm.com → Configure → Polling & Refresh Intervals → Preferred camera transport → Janus proxy**. The preference applies to the entry and falls back when the preferred transport is not offered. This preserves the #172 workaround without forcing every account onto Janus.
- **Camera retries (#177):** A brief connection no longer immediately resets the five-retry budget. Reset requires 30 seconds with a connected peer. Automatic recovery is also limited to ten attempts in ten minutes, then the card shows **Reconnect**. Brief Lovelace reparenting keeps the retry budget and active connection; a genuine dashboard return or manual retry gets a fresh budget.
- **Water valves (#178):** Fetch only system-advertised valve IDs directly rather than waiting indefinitely for device-catalog resources that some accounts omit. Accounts without valves do not query the endpoint. Known OPEN/CLOSED states are preserved; UNKNOWN is no longer shown as open. The provider's `hasState: false` flag alone does not discard an explicit OPEN/CLOSED value. Live valve commands remain unverified and were not sent during development.
- **Setup audit:** Verified that SMS/email selection requests a code before displaying the code form, failed delivery requests stay on the method selector, and resend does not submit a blank code. Added direct tests of the library's SMS/email action endpoints. The current climate imports already use the supported Home Assistant locations. This does not establish why a particular provider fails to deliver an email code; the upstream #558 report needs the installed fork version and delivery/resend details.

Update through HACS, restart Home Assistant, and fully reload browser/app dashboards to load the updated camera card. Test one camera, then the normal multi-camera view, repeated page reloads and 24-hour kiosk use. If endToEnd does not start on your account, choose Janus proxy in the option above. Please report which transport is selected and whether normal viewing recovers; omit streaming credentials and signed URLs from browser logs.

For water-valve testing, first confirm that the valve entity appears and compare its state with the Alarm.com portal. No physical open/close test is required to verify discovery. Report any discovery errors with personal data removed. Water-meter entities and broader naming changes are not included.

Automated validation: 352 Python tests and 15 camera-card tests pass. These exercise code paths, not a 24-hour hardware soak or actual email/SMS delivery. #177 and #178 remain open for live confirmation. The experimental #157 beta sign-in and arming changes are excluded, and published releases are unchanged.
