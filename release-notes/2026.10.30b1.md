# Alarm.com 2026.10.30b1 beta

Changes since **2026.10.30b0**. All b0 reliability, sensor-event, camera-card,
light-color, and switch-scene changes remain included. Stable remains 2026.10.28.

## Missing Z-Wave lights: targeted diagnostics (#115)

This build adds a DEBUG-only comparison of the system-detail response before and
after parsing. It reports predefined structure labels, entry/ID counts, system
match booleans, related-link presence, and a bounded declared count. The probe
itself never logs raw IDs, names, URLs, credentials, or response bodies. Numeric
system IDs and string metadata counts are normalized before comparison.

**This is an investigation update, not a confirmed fix for missing lights.** The
existing discovery requests and ID-scoped retry remain unchanged. The new probe
runs in the fallback path when ordinary discovery finds no lights; a working
account may not produce a probe line.

### Focused test for #115

1. Install this beta and restart Home Assistant to load the new files.
2. Temporarily enable DEBUG for `_pyalarmdotcomajax`. For example, use Developer
   Tools > Actions with the following action, then reload the Alarm.com integration:

   ```yaml
   action: logger.set_level
   data:
     _pyalarmdotcomajax: debug
   ```

3. Copy only lines containing `Light discovery:` or `Light discovery probe:`.
   Also include an `ID-scoped light discovery` result if one appears.
4. Return `_pyalarmdotcomajax` to `info` using the same action after the capture.
   If your previous level differed, restore that level instead.

Those lines should distinguish a populated response being lost by the parser,
a relationship that contains no embedded IDs, and a system-selection mismatch.
The existing relationship count of 33 means 33 relationship names, not 33 lights.

## Thermostat temperature updates

- Apply live ambient-temperature property events, including zero values and
  Celsius conversion, instead of waiting for the periodic full-state poll.
- Display the forwarded/effective temperature, including paired remote sensors,
  when available. Fall back to the thermostat's own reading when absent.
- Preserve a paired or distinct forwarded reading when a single probe changes.
  Request the existing coalesced API refresh to obtain the authoritative average
  and related readings without assuming the probe value equals the average.

Test temperatures against the Alarm.com portal, including updates without an
integration reload. Paired-sensor behavior still needs hardware verification.

## Temporary access for an existing user (#108)

Add `alarmdotcom.set_temporary_access`, with explicit account, system, user, start,
and end fields. Dates require UTC or explicit offsets and an increasing interval.
The action fetches current access immediately before writing, preserves the PIN,
role, and other attributes, and verifies the returned schedule. It does not expose
or require the PIN in the Home Assistant action.

The first version supports an existing user with no weekly schedule and no access
plan. It does not create users, change codes, clear schedules, or grant unrestricted
access. Writes are not automatically replayed after authentication failure. Check
the portal before retrying an unconfirmed update. Server acceptance does not prove
that all locks/panels finished synchronizing. Test with a disposable user first.

See [the access investigation](../docs/investigations/issue-108-temporary-user-access.md)
for a synthetic action example and remaining hardware checks.

## Scope and validation

Camera snapshot endpoint changes, panel-image association, standalone temperature
sensors, and the large upstream controller refactors are not included. Existing
camera credential protection and HTTP payload-log suppression are retained.

Validation: 283 Python regression tests and five camera-card JavaScript tests
pass. Nine independent compatibility checks pass on each of Home Assistant
2026.11.0b0 and 2026.11.0b1. Full-suite tests use Home Assistant 2026.10.4.
Hardware verification remains necessary for the new access and thermostat behavior.
