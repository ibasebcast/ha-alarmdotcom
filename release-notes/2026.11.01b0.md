# 2026.11.01b0, unreleased combined test build

This build is prepared for maintainer testing. No tag or GitHub release has been published. It includes all changes already in 2026.10.30b1.

## Changes

- Camera reconnect recovery requests current credentials, handles rejected legacy tokens, bounds retries, and ignores callbacks from removed dashboard cards (#156).
- Snapshot retrieval uses Alarm.com's signed image URL and a separate cookie-free image download.
- SMS/email verification forms offer an explicit resend option. Authenticator-app behavior is unchanged.
- Temporary-access writes compare timezone-aware instants and perform one read-back when the initial response does not confirm dates. Writes are not automatically replayed (#108).
- New response-only `alarmdotcom.get_temporary_user_schedule` action returns saved dates and Alarm.com's numeric credential status without exposing the PIN (#108).
- README install buttons from PR #155 and dedicated-login permissions guidance (#115/#154).

## Test in one installation

Back up HA, install the integration directory, restart once, and fully reload the browser so it loads the updated card.

1. Open cameras, navigate away for several seconds, and return at least ten times. Check moving timestamps and simultaneous cameras/tabs. Check quick navigation and phone rotation too.
2. Test HA's normal snapshot action on an installed, online camera. Missing/offline devices may not supply images.
3. On the disposable test user, set a known temporary period, then call the read action and compare both dates with the portal. Confirm the false confirmation error is gone. Check the portal before retrying any failed write.
4. Test SMS/email resend during a deliberately initiated setup/reauthentication, if needed. Do not disturb a working login solely for this test.
5. Verify normal sensor events, locks, lights, integration reload, and setup links.

## Limits

Read-back verifies saved server data, not synchronization or timed enforcement on every device. User creation, user-name selection, weekly/access-plan changes, and clearing schedules remain unsupported. Snapshot support still needs live validation across camera models. Doorbell-button events, casting, recording, standalone temperature devices, and panic activation are not added. The speculative light-context branch is excluded; #115 was resolved through login permissions.

Promote only after live validation. Published beta contents remain unchanged.
