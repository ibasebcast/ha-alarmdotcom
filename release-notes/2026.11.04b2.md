# 2026.11.04b2

Opt-in test build for [#157](https://github.com/ibasebcast/ha-alarmdotcom/issues/157), on top of 2026.11.04b1.

- Allow up to 3 minutes for the integration to sign in and load devices when Home Assistant starts or reloads it (was 10 seconds). With b1, adding Alarm.com succeeded, but the entry then showed "Failed to set up, retrying" because its own sign-in could not finish in 10 seconds. Reconnects after a dropped connection use the same limit (was 15 seconds).
- When the entry cannot connect, log an `Alarm.com setup could not connect` warning with the elapsed time and per-step sign-in durations, or note that sign-in finished and device loading stalled. The same detail appears in the entry's retry message. Neither includes credentials or account data.
- Stop sign-in step timing when sign-in completes, so device loading is not counted as a sign-in step.

### What to test

Install this beta in HACS and restart Home Assistant. Your existing Alarm.com entry should load; the first load may take a minute on a slow connection. Report whether the panel and devices appear. If the entry still shows "Failed to set up, retrying", copy the `Alarm.com setup could not connect` warning from **Settings → System → Logs**.

[Stable 2026.11.04.3](https://github.com/ibasebcast/ha-alarmdotcom/releases/tag/v2026.11.04.3) remains the rollback version.
