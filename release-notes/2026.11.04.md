## Alarm.com 2026.11.04

Stable update for installation, session recovery, and temporary-access permissions.

- **Setup and login (#157):** Accept omitted optional session settings and use the legacy keep-alive URL when Alarm.com omits one. Setup identifies the selected system before creating the entry. Home Assistant loads the full device catalog during normal entry initialization. Setup logs identify sign-in, MFA, and active-system lookup by attempt ID, with elapsed time and safe exception names.
- **Session recovery (#162):** Mark affected entities unavailable after an authentication failure during full refresh. Restore availability after a successful refresh. Arm and disarm commands have a 30-second deadline. If a command times out, check the panel before retrying.
- **Temporary access:** Changing a schedule now uses Home Assistant's administrator service registration. The existing read action still returns saved dates and credential status.
- **Diagnostics:** Recent events show basic delivery fields. Raw event payloads and camera network addresses are excluded from diagnostic exports.

The setup changes address specific compatibility gaps. Confirmation on the affected provider and investigation of the recurring 403s are still pending.

Update through HACS and restart Home Assistant. For first-time setup troubleshooting, see [Capture first-time setup logs](https://github.com/ibasebcast/ha-alarmdotcom#capture-first-time-setup-logs).
