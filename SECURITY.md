# Security Policy

## Reporting a vulnerability

Please **do not open a public issue** for security vulnerabilities, leaked credentials, authentication bypasses, or sensitive diagnostic data.

Use GitHub's **Report a vulnerability** option under the repository's Security tab if private vulnerability reporting is enabled. If that option is unavailable, contact the maintainer privately through an established contact channel. Do not send secrets through public issues, discussions, or pull requests.

Include a description, affected integration version, reproduction steps, potential impact, and a redacted proof of concept if available. Do not include live credentials or tokens.

## Supported versions

Security fixes are targeted at the latest stable release. Older releases and beta builds are not guaranteed to receive backports.

## Protect your data

Never publish Alarm.com usernames, passwords, MFA codes, cookies, access or refresh tokens, account identifiers, full diagnostic dumps, or unredacted Home Assistant logs. Review attachments manually before posting. Redact personal addresses, device identifiers, and camera URLs where appropriate.

The maintainers will review reports as capacity permits. No fixed response or remediation timeline is guaranteed.
